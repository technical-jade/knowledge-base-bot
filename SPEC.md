# knowledge-base — база знаний с Telegram-ботом

ТЗ для агента Claude Code на `jade`. Работа рассчитана на **автономный ночной
прогон**: человек отвечает на вопросы этапа 0, выполняет свои шаги и уходит
спать, агент проходит этапы 1–8 сам и утром присылает отчёт.

Документ согласован с человеком 15.10.2026 (сессия брейншторма на MacBook).
Принятые решения не пересматривать; если решение невыполнимо — см. «Правила
автономной работы».

---

## 1. Цель

Человек постоянно учится и просит Claude писать красиво оформленные статьи,
гайды и учебники. Нужно:

1. **База знаний** — приватный репозиторий `knowledge-base` на GitHub: статьи
   в Markdown, сайт на VitePress, разделы по папкам, навигация, поиск,
   адаптив, тёмная тема.
2. **Сайт** — собирается на `jade`, доступен **только в тайлнете**:
   `https://jade.tail2b43aa.ts.net/kb/`.
3. **Бот** `kb-bot` в Telegram — «прокси-Claude», когда человек не у компьютера:
   пишет и правит статьи, публикует их, отвечает на любые вопросы в чате
   (с поиском в интернете), ищет по базе.
4. Править статьи можно и **руками с любой машины**: `git clone` → правка →
   `git push` → боту `/deploy`.

**Критерий успеха:** с телефона написал «напиши гайд по Docker volumes»,
выбрал стиль кнопкой, через несколько минут получил ссылку на опубликованную
красивую статью в нужном разделе; написал «добавь пример с compose» — статья
обновилась.

## 2. Правила автономной работы (прочитать до начала)

1. **Сначала этап 0 целиком.** Всё, что требует человека, собирается
   в начале одним списком. После «всё готово» человек недоступен до утра.
2. **Человека ночью не ждать.** Если шаг заблокирован — записать причину
   в отчёт и переходить к следующему **независимому** шагу. Никогда не
   ослаблять безопасность ради того, чтобы шаг прошёл.
3. **Не трогать:** green (никаких подключений, кроме уже существующих у
   `green-bot`), пользователя `stan` и его ключи, службы `tg-bot`,
   `green-bot`, `code-server`, проект `save-dev`, правила ufw и DOCKER-USER.
   **Не перезагружать** сервер.
4. **Единственная правка общей конфигурации** — добавление пути `/kb`
   в `tailscale serve`. Перед ней сохранить `tailscale serve status --json`,
   после — проверить, что code-server (`/`) и `save-dev` (`:8443`)
   открываются как раньше. Не открываются — откатить и перейти на запасной
   вариант (порт `10000`).
5. **Бэкап перед правкой** любого системного файла (`/etc/...`).
6. **Проверять фактом** (главное правило `jade`): не «конфиг выглядит
   правильно», а «команда отработала, страница открылась, доступ запрещён».
7. **Git.** Коммиты и push в `knowledge-base` и `knowledge-base-bot` —
   только если человек дал на это разрешение в этапе 0 (вопрос В4).
   Без разрешения — работать локально, push оставить на утро. Никогда не
   добавлять строку `Co-Authored-By` в сообщения коммитов.
8. **Комментарии в коде** — по-русски, только где код не говорит сам за себя.
9. **Отчёт** — `~/projects/knowledge-base-bot/REPORT.md` и короткое сообщение
   человеку через новый бот (если этап 4 дошёл до отправки) или через
   `green-bot` (только отправка сообщения его токеном, без изменения его кода).

## 3. Архитектура

### Компоненты (всё на `jade`)

| Компонент | Что делает | Пользователь |
|---|---|---|
| Репозиторий `knowledge-base` (GitHub, приватный) | статьи, VitePress, компоненты, `CLAUDE.md` со стилем | — |
| Рабочая копия `/srv/kb/repo` | `kb` делает pull/commit/push; `kb-claude` пишет **только** в `docs/` | владелец `kb`, группа `kb-docs` |
| Бот `kb-bot` (systemd, Python 3.14, aiogram 3) | Telegram, намерения, очередь, git, проверка, сборка, публикация | `kb` |
| Claude (`claude -p --model opus`) | пишет/правит статьи, отвечает, ищет в интернете. **Без Bash** | `kb-claude` |
| Обёртка `/usr/local/bin/kb-claude-run` | единственный способ запуска Claude ботом (через sudo) | root:root 755 |
| Контейнер сборки | `pnpm install` / `vitepress build` в Docker без секретов; build — **без сети** | — |
| Опубликованный сайт | `/srv/kb/releases/<sha>`, ссылка `/srv/kb/site` | `kb` |
| Раздача статики | маленький HTTP-сервер на `127.0.0.1:8090` + `tailscale serve --set-path /kb` | `kb` |
| Код бота | разработка: `~/projects/knowledge-base-bot` (под `stan`); установка: `/opt/kb-bot` (root, только чтение для `kb`) | — |

Ваш личный `claude` на `jade` (под `stan`) с ботом не пересекается.

### Путь запроса

```
сообщение → это ALLOWED_ID? ── нет → игнор + запись в журнал
              │ да
              ▼
   команда? /new /ask /find /list /delete /undo /deploy /reset /help
              │ нет (свободный текст)
              ▼
   определение намерения (Claude, режим route, без инструментов)
   → new | edit | ask_kb | find | chat | delete | undo | help | to_article
              ▼
   очередь: записывающие задачи — строго по одной;
            чтение (chat/ask/find/help) — параллельно, не более 2
```

## 4. Функции бота

### Команды

| Команда | Что делает |
|---|---|
| `/help` | что умеет бот, команды, примеры, правило «секретов в базу не класть» |
| `/new <тема>` | новая статья (или учебник) |
| `/ask <вопрос>` | вопрос по базе: Claude отвечает по статьям, со ссылками |
| `/find <запрос>` | найти статьи: список ссылок |
| `/list` | разделы и статьи со ссылками |
| `/delete <что>` | удалить статью — только после кнопки подтверждения |
| `/undo` | отменить последнее изменение бота (`git revert`) — с подтверждением |
| `/deploy` | `git pull` → сборка → публикация, без Claude (для ручных правок) |
| `/reset` | начать новый разговор в чате |

### Свободный текст

Без команды намерение определяет Claude (режим `route`, без инструментов,
короткий промпт, ответ — JSON `{"intent": ..., "args": ...}`). Примеры:

| Сообщение | Намерение |
|---|---|
| «Напиши гайд по Docker volumes» | `new` |
| «В DevOps: статья про nginx» | `new`, раздел `devops` |
| «Добавь раздел про compose» | `edit` текущей статьи |
| Ответ (Reply) на сообщение бота со ссылкой + текст | `edit` этой статьи |
| «В статье про Git rebase поправь…» | `edit` названной статьи |
| «Что у меня есть про сети?» | `find` |
| «Что я записывал о volumes?» | `ask_kb` |
| «Чем HTTP/2 отличается от HTTP/3?» | `chat` |
| «Сделай из этого статью» | `to_article` (статья из сессии чата) |
| «Перенеси в Frontend» | `edit` (перенос файла) |
| «Удали статью про X» | `delete` (с подтверждением) |
| «Как тебя использовать?» | `help` (Claude отвечает по описанию бота) |

Не уверен в намерении — Claude возвращает `clarify` с вопросом, бот задаёт
его человеку.

### Новая статья

1. Если в запросе **не указаны** глубина/стиль — inline-кнопки:
   «Простыми словами» · «Разработчику, с нуля в теме» · «Справочник/шпаргалка» ·
   «Учебник из глав». Не выбрано за 10 минут → «Разработчику, с нуля в теме».
   Указаны в тексте («кратко», «простыми словами», «подробный курс») — сразу
   писать.
2. **Раздел:** назван в запросе → туда; не назван → Claude выбирает из
   разделов в `CLAUDE.md` или создаёт новый (с `index.md` раздела) и
   сообщает, куда положил.
3. **Формат:** обычно одна страница; «Учебник из глав» или «курс/учебник»
   в запросе → папка `docs/courses/<тема>/` с `index.md` (оглавление)
   и главами `01-….md`, `02-….md`; навигация «далее/назад».
4. Дальше — «Конвейер изменения» (раздел 6).

### Правка

- **Текущая статья** — последняя написанная/правленная ботом.
- Правка продолжает **сессию Claude этой статьи** (`--resume`), поэтому
  понимает «сделай короче», «верни как было в третьем разделе».
- Правка ответом на сообщение бота — бот хранит `message_id → путь статьи`.
- Перенос в другой раздел — `git mv` делает бот по ответу Claude (у Claude
  нет git; он сообщает новый путь в итоговом JSON, см. разделы 5 и 6).

### Чат

- Одна сессия чата (`--resume`), сбрасывается `/reset`.
- Claude отвечает на любые вопросы с поиском в интернете; может читать
  статьи базы.
- «Сделай из этого статью» — новая статья, написанная в **той же сессии
  чата** (помнит разговор), дальше — конвейер изменения.

### Статусы

Длинные задачи показывают ход работы **одним редактируемым сообщением**
(не чаще раза в 3 с): «Ищу: …», «Читаю: <домен>», «Пишу: devops/docker.md»,
«Собираю сайт…», «Публикую…». Источник — события `--output-format
stream-json`. В конце — итог: «Готово: <ссылка> (раздел DevOps)».

## 5. Claude: обёртка, режимы, изоляция

### Пользователи и права

- `kb` — системный пользователь бота, `/home/kb`, без входа по SSH.
- `kb-claude` — системный пользователь Claude, `/home/kb-claude`, без
  входа по SSH, ничего секретного в домашней папке, кроме своего токена.
- Группа `kb-docs` = `kb` + `kb-claude`. `/srv/kb/repo/docs` — группа
  `kb-docs`, `2775` (setgid), umask обоих 002 для файлов в `docs/`.
  Всё остальное в `/srv/kb/repo` (включая `.git`, `.vitepress`,
  `package.json`, `CLAUDE.md`) — только чтение для `kb-claude`.
- Проверить фактом от имени `kb-claude`:
  - запись в `docs/` — можно; в `.vitepress/`, `.git/`, `CLAUDE.md` — нельзя;
  - чтение `/home/stan`, `/home/kb`, `/etc/kb-bot/` — **Permission denied**
    (`/home/stan` уже `750` — подтвердить).

### Секреты

| Секрет | Файл | Права |
|---|---|---|
| Токен Telegram | `/etc/kb-bot/env` (`BOT_TOKEN`, `ALLOWED_ID`) | `kb:kb 600` |
| Deploy key `knowledge-base` (запись) | `/home/kb/.ssh/id_ed25519_kb` | `kb 600` |
| Токен Claude (`CLAUDE_CODE_OAUTH_TOKEN`) | `/etc/kb-claude/token` | `kb-claude 600` |

Секреты **не попадают в транскрипт агента**: агент создаёт пустые файлы
с правильными правами, а значения человек вписывает сам командами из этапа 0.

### Обёртка `kb-claude-run`

- sudo-правило: `kb ALL=(kb-claude) NOPASSWD: /usr/local/bin/kb-claude-run`
  (файл в `/etc/sudoers.d/`, проверка `visudo -c`). sudo сбрасывает
  окружение — переменные бота до Claude не доходят.
- Аргументы: `<mode> [--resume <uuid>]`; промпт — через stdin. Режимы
  жёстко зашиты, лишние аргументы — ошибка. `uuid` проверяется регуляркой.
- Обёртка читает токен из `/etc/kb-claude/token`, `cd /srv/kb/repo`,
  запускает `claude -p --model opus --output-format stream-json --verbose`
  с инструментами по режиму:

| Режим | Инструменты | Для чего |
|---|---|---|
| `route` | никаких | определение намерения (JSON) |
| `read` | Read, Glob, Grep, WebSearch, WebFetch | чат, `ask_kb`, `find`, `help` |
| `write` | Read, Glob, Grep, Edit, Write, WebSearch, WebFetch | новая статья, правка, перенос, удаление |

- Всегда `--disallowedTools Bash` (и прочие, не перечисленные). Дополнительно
  `/home/kb-claude/.claude/settings.json` с `permissions.deny` на `Bash`.
- Системные инструкции для каждого режима — файлы в `/opt/kb-bot/prompts/`
  (`--append-system-prompt`): кто пользователь, как устроена база, как
  отвечать, формат итогового JSON, описание бота для вопросов «как тебя
  использовать».
- Итог режима `write` — последний блок ответа Claude в виде JSON:
  `{"action": "created|edited|moved|deleted", "files": [...],
  "primary": "docs/devops/docker-volumes.md", "section": "devops",
  "summary": "…"}`. Бот проверяет, что пути внутри `docs/`.
- Claude Code для `kb-claude` ставится нативным установщиком в его
  домашнюю папку (у `stan` бинарник в `~/.local/bin` недоступен — `750`).
- Таймаут одной задачи — 20 минут (по истечении — kill и сообщение).
- Ошибка авторизации (401, «Invalid API key», «/login») — отдельное
  сообщение человеку: «Claude не авторизован: обнови токен
  (`claude setup-token`)» с командой обновления файла.

### Проверка фактом (этап 3)

От `kb` через sudo: режим `write` — попросить выполнить `ls /home` →
отказ (нет Bash); попросить прочитать `/etc/kb-bot/env` → Permission
denied; попросить записать файл в `.vitepress/` → Permission denied;
написать тестовую статью в `docs/` → появилась.

## 6. Конвейер изменения (бот, под `kb`)

1. `git -C /srv/kb/repo pull --ff-only`. Не прошло → сообщить, задачу не
   начинать.
2. Claude в режиме `write` (новая сессия или `--resume` сессии статьи).
3. **Охрана границ:** `git status --porcelain` — изменения только в `docs/`.
   Иначе — откатить всё (`git checkout -- . && git clean -fd docs/`),
   сообщить, записать в журнал.
4. **Проверка Markdown** (бот, без Claude) по изменённым файлам, вне
   блоков кода и inline-кода:
   - запрещены `<script`, `<style`, `<iframe`, атрибуты `on*=`,
     `javascript:`, `{{ … }}` (интерполяция Vue выполняется при сборке);
   - теги-компоненты (с заглавной буквы или с дефисом) — только из белого
     списка: файлы `.vitepress/theme/components/*.vue` + встроенные
     `Badge`, `OutboundLink`; обычный HTML без скриптов — можно;
   - обязательный frontmatter: `title`, `description`, `tags`, `level`,
     `created`, `updated`, `sources` (может быть пустым).
   Нарушение → текст ошибок отправляется Claude в той же сессии
   («исправь»), до 2 попыток; потом — откат и сообщение.
5. **Сборка** (раздел 7). Упала → лог Claude в той же сессии, до 2 попыток;
   потом — откат и сообщение с хвостом лога.
6. `git add docs && git commit` от имени `kb-bot <kb-bot@jade>`; сообщение
   коммита — по-русски, из `summary` Claude: «Статья: Docker volumes» /
   «Правка: Docker volumes — раздел про compose».
7. `git pull --rebase`; конфликт → `git rebase --abort`, сохранить diff
   в `/srv/kb/conflicts/<время>.patch`, вернуть репозиторий к `origin`,
   сообщить человеку: что конфликтует и где патч. Молча не разрешать.
8. `git push`.
9. Публикация (раздел 7).
10. Ответ: ссылка на `primary`, раздел; статья становится текущей; сессия
    Claude привязывается к статье.

`/undo`: последний коммит в `main` должен быть от `kb-bot` — иначе отказ
с пояснением; иначе подтверждение → `git revert` → сборка → push →
публикация. `/delete`: подтверждение → Claude в режиме `write` находит
файлы статьи, убирает ссылки на неё из других статей и возвращает
`{"action": "deleted", "files": [...]}`; **удаляет файлы бот** (`git rm`) —
у Claude нет Bash, а Write удалять не умеет. Перенос — так же: Claude
возвращает `{"action": "moved", "from": ..., "to": ...}`, бот делает
`git mv`, затем Claude правит ссылки → обычный конвейер.

## 7. Сборка и публикация

### Сборка в контейнере

- Образ `kb-build` (Dockerfile в `knowledge-base-bot/deploy/`): Node 24 LTS,
  pnpm через corepack, версия pnpm — из `packageManager` репозитория.
- **Установка зависимостей** — отдельный запуск **с сетью**, но без
  секретов, `pnpm install --frozen-lockfile --ignore-scripts`, кэш
  `node_modules` в томе `kb-node-modules`; повторяется только при
  изменении `pnpm-lock.yaml`. `package.json`/lockfile Claude менять не
  может — это доверенный ввод.
- **Сборка** — `--network none`, `--read-only`, репозиторий смонтирован
  только для чтения и копируется во временную папку внутри контейнера,
  результат — в том вывода. Без секретов, `--user` не root,
  `--memory 1.5g`, `--cpus 2`.
- Порты контейнер не публикует — DOCKER-USER не затрагивается.

### Публикация

- Вывод сборки → `/srv/kb/releases/<короткий sha>`; атомарная замена
  ссылки `/srv/kb/site` (`ln -sfn` во временное имя + `mv -T`).
  Хранить 5 последних релизов.
- Раздача: служба `kb-web` (systemd, пользователь `kb`) — статический
  HTTP-сервер на `127.0.0.1:8090`, корень `/srv/kb/site`. Взять простой и
  проверенный вариант (например, Caddy из официального репозитория или
  `python -m http.server` за `tailscale serve` — на выбор агента, с
  обоснованием в отчёте); `base` VitePress — `/kb/`.
- `sudo tailscale serve --bg --set-path /kb http://127.0.0.1:8090` (см.
  правило 4 в разделе 2). Запасной вариант — `--https=10000`, `base: '/'`.
- Проверка фактом: с `jade` `curl` по адресу тайлнета → 200, HTML сайта;
  code-server и `save-dev` по-прежнему открываются.

## 8. Репозиторий `knowledge-base`

```
knowledge-base/
├── CLAUDE.md                 правила для Claude (см. ниже)
├── README.md                 для человека: как править руками, /deploy
├── package.json              vitepress, vitepress-plugin-mermaid; packageManager: pnpm@<актуальная>
├── pnpm-lock.yaml
├── .vitepress/
│   ├── config.ts             srcDir: 'docs', base: '/kb/', ru, тёмная тема, локальный поиск, mermaid
│   ├── sidebar.ts            меню из папок docs/ и frontmatter (своя небольшая функция)
│   └── theme/
│       ├── index.ts          регистрация компонентов
│       ├── custom.css
│       └── components/       Card.vue, CardGrid.vue, Steps.vue, Compare.vue (белый список)
└── docs/
    ├── index.md              главная: разделы + последние статьи (createContentLoader)
    ├── <раздел>/index.md     название и описание раздела
    ├── <раздел>/<статья>.md
    └── courses/<тема>/       учебники: index.md + 01-….md …
```

- `srcDir: 'docs'` — конфиг и компоненты лежат **вне** `docs/`, поэтому
  Claude их не может менять.
- Меню строится само: раздел = папка, порядок — по `order` во frontmatter
  или по алфавиту; учебники — по номеру главы.
- Поиск — встроенный локальный, должен находить по-русски (проверить).
- Mermaid, блоки `::: tip/warning/danger/details`, группы кода — включены.

### `CLAUDE.md` репозитория (пишет агент на этапе 1)

- Читатель — один человек: опытный фронтенд-разработчик, изучает новые
  темы. Язык — русский, термины и код — в оригинале.
- Стили (`level` во frontmatter): `simple` — простыми словами, аналогии;
  `dev` — разработчику, с нуля в теме: зачем, как устроено, практика,
  подводные камни (по умолчанию); `reference` — справочник/шпаргалка;
  `course` — учебник из глав.
- Структура статьи по умолчанию: о чём и зачем → суть → примеры →
  подводные камни → шпаргалка → источники.
- Стартовые разделы: `devops`, `frontend`, `backend`, `networking`,
  `tools`, `misc`, `courses` (можно создавать новые, с `index.md`).
- Компоненты: что делает каждый, пример использования; что запрещено
  (раздел 6, шаг 4).
- Имена файлов — латиница, kebab-case.
- **Секреты (пароли, токены, рабочие данные) в базу не класть.**
- Факты из интернета — со ссылками в `sources`; свежие версии проверять
  поиском.

## 9. Бот: устройство кода

- Python 3.14, aiogram 3, venv, зависимости зафиксированы в
  `requirements.txt`. Структура — по образцу `~/projects/green-bot`
  (прочитать его `SPEC.md` и код: стиль, деплой, тесты).
- Состояние — SQLite `/var/lib/kb-bot/state.db`: сессия чата, текущая
  статья, `статья → сессия Claude`, `message_id → статья`, журнал задач
  (время, намерение, итог, коммит, длительность).
- Ответы Telegram: Markdown Claude → HTML Telegram с разбиением по 4096
  символов; ошибка разметки → повтор простым текстом.
- Только `ALLOWED_ID`; остальные — игнор + журнал.
- CLI для самопроверки: `kb-bot-cli "<текст>"` — тот же конвейер без
  Telegram (вывод в терминал). Нужен для ночных тестов.
- Установка: `deploy/install.sh` — копирует код в `/opt/kb-bot` (root),
  создаёт venv, ставит службы `kb-bot` и `kb-web`, обёртку, sudoers.
- systemd `kb-bot`: `User=kb`, `EnvironmentFile=/etc/kb-bot/env`,
  `Restart=on-failure`, `MemoryMax=2G`, `CPUQuota=200%`,
  `NoNewPrivileges` **нельзя** (нужен sudo) — остальное ужесточение
  (`ProtectSystem=strict` с `ReadWritePaths=/srv/kb /var/lib/kb-bot
  /home/kb-claude`, `ProtectHome=read-only`, `PrivateTmp`) — дочерние
  процессы (sudo → Claude, sudo → Docker) наследуют эти ограничения:
  Claude пишет в `~/.claude` своей домашней папки, Docker — в свой сокет.
  Проверить фактом, что ужесточение не ломает ни то, ни другое.
- Доступ `kb` к Docker: группа `docker` = root-эквивалент. Вместо этого —
  узкое sudo-правило на скрипт `/usr/local/bin/kb-build-run` (root:root,
  фиксированные аргументы), который запускает контейнер сборки.
- Тесты (pytest): проверка Markdown (запрещённое и белый список),
  разбор намерения/JSON, охрана границ `docs/`, git-операции на временном
  репозитории (коммит, конфликт, revert), разбиение сообщений,
  валидация аргументов обёрток.

## 10. Этапы

### Этап 0 — подготовка с человеком (до ухода человека)

Агент **одним сообщением** задаёт вопросы и выдаёт инструкции, ждёт ответы,
выполняет подготовку и проверяет каждую вещь фактом. Только после проверки
всего — сообщение «Можно идти спать».

**Вопросы человеку:**

- **В1.** SSH-адрес репозитория `knowledge-base` на GitHub (создать
  **приватным и пустым**, без README).
- **В2.** SSH-адрес репозитория `knowledge-base-bot` (тоже приватный,
  пустой) — или разрешение хранить код бота только на `jade`.
- **В3.** Имя и @username нового бота, созданного в BotFather (не
  `@jade_green_bot`).
- **В4.** Разрешение на коммиты и push в `knowledge-base` и
  `knowledge-base-bot` на всё время выполнения этой спецификации.
- **В5.** Подтверждение адреса сайта `https://jade.tail2b43aa.ts.net/kb/`.

**Подготовка агентом (сразу после ответов):**

1. Создать пользователей `kb`, `kb-claude`, группу `kb-docs`, папки
   `/etc/kb-bot`, `/etc/kb-claude`, `/srv/kb`, `/var/lib/kb-bot`; пустые
   файлы секретов с правами из раздела 5.
2. Сгенерировать deploy key для `kb`, показать **публичную** часть.
3. Проверить, что `stan` своим ключом `~/.ssh/id_ed25519` (GitHub
   `russian-stan`) имеет доступ к **обоим** репозиториям: каркас
   `knowledge-base` (этап 1) делается в `~/projects/knowledge-base` под
   `stan` и пушится этим ключом; deploy key `kb` нужен боту.
4. `ALLOWED_ID` взять из `~/projects/green-bot/.env` и записать в
   `/etc/kb-bot/env` (это не секрет; значение в транскрипт не выводить).

**Шаги человека (агент выдаёт готовые команды):**

- Добавить deploy key в `knowledge-base` → Settings → Deploy keys,
  **Allow write access**.
- Записать токен бота:
  `sudo sh -c 'read -r t; echo "BOT_TOKEN=$t" >> /etc/kb-bot/env'`
  (вставить токен, Enter).
- Получить токен Claude: `claude setup-token` (на MacBook или `jade`) и
  записать: `sudo -u kb-claude sh -c 'read -r t; printf "%s" "$t" > /etc/kb-claude/token'`.
- Написать новому боту `/start` в Telegram (иначе бот не сможет написать
  первым).

**Проверки агентом перед «можно спать»:** deploy key — `git ls-remote`
от `kb` проходит **и** тестовый push в ветку `kb-check` (затем удалить
ветку); токен бота — `getMe` отвечает (значение не печатать); токен
Claude — после установки Claude Code для `kb-claude`: `claude -p "ответь ok"`
от `kb-claude` отвечает; push `stan` в `knowledge-base-bot` — `git ls-remote`.

### Этап 1 — каркас `knowledge-base`

Структура из раздела 8, тема, 4 компонента, `CLAUDE.md`, `README.md`,
стартовые разделы с `index.md`, 3 пробные статьи разных стилей (например:
«Как пользоваться этой базой знаний», `devops` — «Docker volumes»,
`reference` — «Шпаргалка Git»). Локальная сборка проходит, поиск находит
по-русски, Mermaid рисуется. Коммит и push (если В4).

**Готово, когда:** `pnpm build` проходит, в статьях использованы все
компоненты, проверка Markdown из раздела 6 (уже написанная в коде бота)
их пропускает.

### Этап 2 — публикация на `jade`

Клон в `/srv/kb/repo` от `kb`, права `docs/` (раздел 5), образ `kb-build`,
`kb-build-run` + sudo, скрипт публикации, `kb-web`, `tailscale serve /kb`.

**Готово, когда:** сайт открывается по `https://jade.tail2b43aa.ts.net/kb/`
(curl с `jade` через тайлнет → 200, ссылки и стили на месте с учётом
`base`), code-server и `save-dev` открываются, сборка без сети проходит,
откат на прошлый релиз работает.

### Этап 3 — Claude в изоляции

Claude Code для `kb-claude`, обёртка `kb-claude-run`, sudoers,
`settings.json`, промпты режимов.

**Готово, когда:** все проверки из «Проверка фактом (этап 3)» раздела 5
пройдены; статья, написанная через обёртку в режиме `write`, проходит
проверку Markdown и сборку.

### Этап 4 — ядро бота

Каркас aiogram, `ALLOWED_ID`, `/help`, чат с памятью, `/reset`,
определение намерения, очередь, статусы, уведомление об ошибке
авторизации, `kb-bot-cli`, служба `kb-bot`.

**Готово, когда:** бот запущен как служба; через `kb-bot-cli` чат отвечает
и помнит предыдущую реплику; намерения из таблицы раздела 4 определяются
верно (прогнать все примеры, результат — в отчёт); бот прислал человеку
сообщение «kb-bot запущен».

### Этап 5 — статьи

Новая статья (кнопки стиля, раздел, учебник), правка (текущая, ответом,
по названию, перенос), конвейер изменения целиком, конфликты.

**Готово, когда:** через `kb-bot-cli` создана статья и учебник из 2 глав,
сделана правка с `--resume` («сделай короче второй раздел»), всё
опубликовано и открывается; искусственный конфликт (параллельный коммит
от `stan` в клоне) даёт сообщение и патч, репозиторий цел.

### Этап 6 — остальное

`/find`, `/ask`, `/list`, `/delete`, `/undo`, `/deploy`, «сделай из этого
статью».

**Готово, когда:** каждое проверено через `kb-bot-cli`; `/undo` отменяет
только коммит бота; `/delete` без подтверждения ничего не удаляет.

### Этап 7 — надёжность

Лимиты systemd, журнал, ротация (`/var/lib/kb-bot`, `/srv/kb/releases`,
`/srv/kb/conflicts`), `systemctl restart` бота и `kb-web` не теряет
состояние, автозапуск `enabled`. **Перезагрузку сервера не делать** —
в отчёте пометить «автозапуск после перезагрузки не проверен».

### Этап 8 — отчёт и документация

- `REPORT.md`: что сделано по этапам, что проверено и как, что не
  получилось и почему, что нужно от человека утром, адрес сайта, примеры
  первых сообщений боту.
- `README.md` в `knowledge-base-bot`: устройство, установка, обновление
  токена Claude, откат.
- Обновить `~/CLAUDE.md` на `jade`: короткий раздел о `kb-bot`
  (пользователи, пути, службы, адрес, как перезапустить).
- Сообщение человеку через `kb-bot`: итог и ссылка на сайт.
