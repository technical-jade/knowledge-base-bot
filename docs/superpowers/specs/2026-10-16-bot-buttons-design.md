# Кнопочное управление kb-bot — дизайн

Дата: 2026-10-16. Утверждено человеком в чате (вариант «разделы → карточки»
и все четыре дополнения).

## Цель

Управлять базой знаний в основном кнопками, а не текстом: просмотр по
разделам, правка/удаление/перенос статьи в одно-два нажатия, быстрые
правки, отмена и остановка задач. Текстовые сценарии (свободный текст,
Reply, команды) продолжают работать как раньше.

Критерий успеха: от `/list` до запуска правки или удаления любой статьи —
не больше трёх нажатий; ни одно нажатие не ломает существующие сценарии;
всё, кроме самих нажатий в Telegram, проверяется через `kb-bot-cli`.

## Ограничения Telegram, учтённые в дизайне

- Кнопки — только под сообщением, рядами; в ряду кнопки равной ширины.
- Раскладка (правка после живой проверки): каждая кнопка — во всю ширину;
  две подряд в один ряд — только если обе короткие (≤ 16 символов,
  `ui.SHORT`); кнопок-значков без текста нет.
- `callback_data` ≤ 64 байт → в кнопках короткие коды, не пути.
- ≤ 100 кнопок на сообщение → постраничный вывод (10 статей на страницу).
- Навигация редактирует то же сообщение (`edit_message_text`), а не шлёт новое.

## Экраны (`kbbot/ui.py`)

Чистые функции: данные → `Screen(md, buttons)`. Кнопка — `Btn(label,
action)` или `Btn(label, url=…)`. Telegram и CLI только отображают.

1. **Разделы** (`/list`, «⬅️ Разделы»): «📚 База знаний — N статей» + ссылка
   на сайт; кнопки `«<иконка> <Название> (k)»` (по две, если короткие). Иконка — поле
   `icon` во frontmatter `index.md` раздела, иначе по умолчанию:
   devops ⚙️, frontend 🎨, backend 🗄, networking 🌐, tools 🛠, courses 🎓,
   misc 📦, прочие 📁. Последний ряд: `[🕘 Недавние]`.
2. **Раздел**: «<иконка> <Название> — k статей[, стр. n/m]»; на статью два
   ряда: `[📄 <название>]` во всю ширину и `[✏️ Изменить] [🗑 Удалить]`;
   при k > 10 — ряд `[◀️ Назад] [Дальше ▶️]`;
   последний ряд `[⬅️ Разделы] [➕ Новая]`. Для «Учебники» статья = учебник
   (его `index.md`). Пустой раздел — текст «Пока пусто» и те же нижние кнопки.
3. **Карточка статьи**: «📄 <Название>», описание, «обновлено <updated> ·
   <Раздел>», ссылка на страницу; для учебника — число глав. Кнопки:
   `[🌐 Открыть](url) [✏️ Править] [🔀 Перенести]`,
   `[✨ Короче] [🧒 Проще] [➕ Примеры] [🔄 Факты]`,
   `[🗑 Удалить] [⬅️ <Раздел>]`.
4. **Выбор раздела для переноса**: «Куда перенести «X»?», кнопки разделов
   (кроме текущего и «Учебники»), `[⬅️ Назад]` к карточке.
5. **Недавние** (`/recent`, «🕘 Недавние»): последние 10 коммитов `main`
   («дата · 🤖/✍️ · сообщение»); кнопки карточек для статей, затронутых
   коммитами (до 8, существующих); если последний коммит от бота —
   `[↩️ Отменить последнее]`; `[⬅️ Разделы]`.

## Коды действий

Формат `<verb>:<arg>[:<arg2>]`, всё ASCII, ≤ 64 байт (проверяется тестом).
`<ref>` — целый номер статьи из таблицы `refs` (см. ниже).

| Код | Что делает | Claude |
|---|---|---|
| `home` | экран «Разделы» (edit) | нет |
| `sec:<key>:<page>` | экран раздела (edit) | нет |
| `card:<ref>` | карточка (edit) | нет |
| `recent` | «Недавние» (edit) | нет |
| `ed:<ref>` | новое сообщение «✏️ Что изменить в «X»?» с ForceReply | — |
| `q:<preset>:<ref>` | быстрая правка: `short`, `simple`, `examples`, `facts` | да |
| `mv:<ref>` | экран выбора раздела (edit) | нет |
| `mvto:<ref>:<key>` | перенос в раздел (существующий [move]) | да |
| `del:<ref>` | удаление с подтверждением (существующий `do_delete`) | да |
| `new:<key>` | новое сообщение «➕ Тема новой статьи в <Раздел>?» с ForceReply | — |
| `undo` | существующий `cmd_undo` (с подтверждением) | нет |
| `stop:<task>` | остановить задачу | нет |

Тексты быстрых правок (инструкция для [edit]):
`short` — «Сократи статью: убери повторы и воду, сохрани суть, примеры и
структуру»; `simple` — «Перепиши проще: короче фразы, меньше жаргона,
поясни термины»; `examples` — «Добавь практические примеры там, где их не
хватает»; `facts` — «Проверь поиском актуальность фактов, версий и команд;
исправь устаревшее и обнови источники».

## ForceReply-подсказки

`ed:` и `new:` шлют новое сообщение с `ForceReply` (поле ответа открывается
само). Store запоминает `message_id → (kind, arg)` в таблице `prompts`.
Ответ (Reply) на такое сообщение обрабатывается **без маршрутизатора**:

- `edit` → `do_edit(target=path, instruction=текст)`;
- `new` → `do_new(topic=текст, section=key, style=None)` (стиль — кнопками).

Ответ на обычное сообщение бота о статье — как раньше, через маршрутизатор.

## Кнопки под результатом

Сообщение «Готово/Обновлено/Перенесено: <ссылка>» получает:
`[🌐 Открыть](url) [✏️ Править]`, `[🔀 Перенести]`, `[↩️ Отменить] [🗑 Удалить]`. «Удалено» —
`[↩️ Отменить] [📚 Список]`. `↩️` вызывает `cmd_undo`, который сам
проверяет, что последний коммит — от бота, и спрашивает подтверждение.

## `/find` и поиск свободным текстом

Ответ Claude как раньше; под ним — кнопки карточек (до 8) для статей, чьи
пути `docs/…` или URL сайта встречаются в ответе.

## Остановка задачи

- `Core._run` запускает работу как `asyncio.Task`, регистрирует её в
  `self._running[task_id]`; статусное сообщение «⏳ …» получает кнопку
  `[✖️ Остановить]` (`stop:<task_id>`).
- `stop` отменяет задачу (`task.cancel()`). Ждущая в очереди — просто
  снимается. `claude.run` при `CancelledError` убивает процесс (`_kill`:
  SIGTERM → SIGKILL) и пробрасывает отмену; `change()` уже откатывает
  рабочую копию на любом `BaseException`.
- С начала коммита (`repo.commit`) до публикации задача помечается
  «критической»: `stop` отвечает «Уже публикуется — отменить можно ↩️»,
  отмена не выполняется.
- Итог: «✖️ Остановлено, изменения отменены»; журнал задач — `stopped`.
- Нажатие `stop` для завершившейся задачи — «Задача уже завершена».

## Устаревшие кнопки

Каждое действие с `<ref>` сначала проверяет, что файл существует. Нет —
ответ на нажатие «Статьи уже нет» и экран «Разделы». Неизвестный раздел —
то же. Повторное нажатие деструктивных кнопок безопасно: удаление и
отмена всегда спрашивают подтверждение.

## Хранение (`store.py`)

- `refs(id INTEGER PRIMARY KEY, path TEXT UNIQUE)` — стабильный номер пути;
  при переносе `rename_article` обновляет путь, при удалении запись
  остаётся (кнопка покажет «Статьи уже нет»).
- `prompts(message_id INTEGER PRIMARY KEY, kind TEXT, arg TEXT, created REAL)`
  — ForceReply-подсказки; ротация вместе с `messages`.

## Интерфейсы

- `Responder.send(md, article=None, buttons=None) -> int | None`
- `Responder.edit(message_id, md, buttons=None)` — сменить сообщение на месте.
- `Responder.ask(md, kind, arg) -> int | None` — сообщение с ForceReply.
- `Responder.status(...)` — получает id задачи для кнопки «Остановить».
- `Core.handle_action(action, resp, message_id)` — разбор нажатий;
  Telegram вызывает его из `callback_query` (кроме `ch:` — выбор в
  `choose`, как сейчас), сразу отвечая `cb.answer()`.
- `Core.handle(text, resp, reply_to)` — сначала проверяет `prompts`.
- Действия с Claude идут через `_run` → та же очередь записи; навигация —
  мгновенно, вне очереди.

## CLI

`kb-bot-cli` печатает кнопки под сообщением: `[✏️ ed:12] [🗑 del:12]`;
`kb-bot-cli --press <код> [--msg <id>]` выполняет нажатие;
`--reply <id> "текст"` уже есть и работает с ForceReply-подсказками.

## Меню и справка

`/recent` — в `setMyCommands`, `HELP`, `prompts/about.md`. В справку —
строка «/list — разделы и статьи с кнопками».

## Тесты

- `ui`: экраны разделов, раздела (пагинация, пустой), карточки (статья и
  учебник), переноса, недавних; все `callback_data` ≤ 64 байт.
- `handle_action`: навигация, `ed`/`new` → ForceReply → ответ запускает
  правку/создание без маршрутизатора (заглушка Claude), быстрые правки,
  перенос, удаление, устаревший `ref`.
- Остановка: отмена во время работы заглушки Claude → откат, `stopped`;
  отказ в критической фазе; снятие из очереди.
- `claude.run`: отмена убивает процесс.
- Регресс: существующие 99 тестов зелёные.

## Проверка вживую

`kb-bot-cli --press home`, `sec:devops:0`, `card:<ref>`, `q:short:<ref>` на
тестовой статье с последующим `undo`; `stop` во время задачи; перезапуск
`kb-bot`, `getMyCommands` содержит `/recent`. Нажатия в Telegram — человек.

## Вне рамок

Голосовые сообщения, постоянная нижняя клавиатура (reply keyboard),
откат произвольного (не последнего) коммита, массовые операции.
