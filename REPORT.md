### 1. Каркас `knowledge-base`
- VitePress 1.6.4, `vitepress-plugin-mermaid` 2.0.17 + mermaid 11.17.2,
  pnpm 12.11.2. `base: '/kb/'`, ru, тёмная тема по умолчанию, локальный поиск,
  меню из папок (`sidebar.ts`), у учебников своё меню (далее/назад не уходят
  из курса). Главная и страницы разделов строят списки статей сами
  (тема, вне `docs/`).
- Компоненты (белый список): `Card`, `CardGrid`, `Steps`, `Compare` + `Badge`.
  Все использованы в трёх стартовых статьях; проверка Markdown их пропускает.
- `CLAUDE.md` со стилями, структурой, разделами, компонентами и запретами.
- **Найдено фактом:** VitePress выполняет `{{ … }}` **даже в inline-коде и
  таблицах** (не только в тексте); при ошибке рендера сборка завершается
  с кодом 0 и публикует пустую страницу. Поэтому:
  проверка Markdown запрещает `{{` вне блоков ``` и `::: v-pre`; скрипт
  сборки считает ошибкой любые `…Error` в логе.
- Поиск по-русски: «резервная копия», «бэкап», «отмена коммита»,
  «заимствование» находят нужное (и по индексу, и в браузере).

### 2. Публикация
- `/srv/kb/repo` (клон от `kb`), `docs/` — `kb-docs 2775`, остальное
  `kb-claude` только читает, `.git` — только `kb`.
- Образ `kb-build` (node 24.22, pnpm через corepack). Установка зависимостей —
  отдельный запуск с сетью, тома `kb-node-modules`/`kb-pnpm-store`, повтор
  только при смене lockfile. Сборка — `--network none --read-only`, не root,
  `--memory 1.5g --cpus 2`, `--cap-drop ALL`; проверено: `fetch` в контейнере
  → `EAI_AGAIN`. Сборка ~16 с.
- `kb` не в группе `docker`: `sudo kb-build-run install|build` (фиксированные аргументы).
- Релизы `/srv/kb/releases/<sha>` (хранятся 5), атомарная ссылка `/srv/kb/site`;
  откат `python -m kbbot.publish rollback` — проверен.
- **kb-web — свой маленький модуль на `http.server` (stdlib)**, а не Caddy:
  в Ubuntu Caddy 2.6.2 (старый) и пакет по умолчанию запускает службу на :80
  всех интерфейсов. Модуль: только `127.0.0.1:8090`, без листинга каталогов,
  404.html VitePress, редирект с сохранением `/kb`, кэш для `assets/`.
  Служба с полным ужесточением (`ProtectSystem=strict`, `IPAddressDeny=any`
  кроме localhost, `NoNewPrivileges`, 256 МБ).
- `tailscale serve --set-path /kb` — бэкап `backup/tailscale-serve-before.json`
  (вне git). После: `/` → 302 `/login` (code-server, как было), `:8443` → 200
  (save-dev), `/kb/` → 200, ассеты 200, несуществующее → 404. Запасной порт
  10000 не понадобился.
- В браузере (headless Chromium): Mermaid рисуется, компоненты на месте,
  тёмная тема, поиск, ширина 390 px без горизонтальной прокрутки, ошибок JS нет.

### 3. Claude в изоляции
- Claude Code 2.1.301 для `kb-claude` (`~/.local/bin`), обёртка
  `kb-claude-run <route|read|write> [--resume uuid]`, sudoers (`visudo -c`).
  Режимы: route — без инструментов, read — Read/Glob/Grep/WebSearch/WebFetch,
  write — плюс Edit/Write. Bash нет ни в одном. Модель `opus` → `claude-opus-5-5`.
- Проверено от `kb` через sudo:
  - `ls /home` — нечем (Bash нет в инструментах);
  - чтение `/etc/kb-bot/env`, ключа `kb` — отказ;
  - запись в `.vitepress/`, правка `CLAUDE.md` — отказ;
  - тестовая статья в `docs/` — создана, проверка Markdown и сборка прошли.
- Второй слой (без deny-правил Claude, только права ОС): `EACCES` на
  `/etc/kb-bot/env`, `/home/stan/…`, `.vitepress/`, `package.json`.
- **Найдено фактом:** Write пишет через временный файл + `rename`, поэтому
  принадлежащий root `settings.json` в папке `kb-claude` можно было бы
  подменить целиком (а через hooks получить командную строку). Закрыто:
  `chattr +i` (проверено: `mv` поверх → `Operation not permitted`) и deny
  на запись в `/home`, `/tmp`, `/etc`, `/var`….
- Ужесточение службы `kb-bot` проверено через `systemd-run` с теми же
  свойствами: Claude, Docker-сборка и git работают.
- Ошибка авторизации Claude → отдельное сообщение с командой обновления токена (тест).
- Таймаут 20 мин: `kb` может завершить `sudo`, тот передаёт сигнал Claude
  (проверено); страховка — `timeout 1500` внутри обёртки.

### 6. Остальное
- `/deploy` (ручной push → сборка → публикация), `/list`, `/find`, `/ask` — работают.
- «Сделай из этого статью» — статья в той же сессии чата (Cache-Control).
  **Найдено и исправлено:** сессия чата создана в режиме read и не знает формат
  итогового JSON (Claude отвечал `"action": "create"`); и после отката неудачной
  попытки «помнила», что статья уже написана. Теперь каждый промпт записи несёт
  спецификацию JSON, продолжение сессии — пометку «сверяйся с файлами», а разбор
  понимает синонимы.
- Перенос в Frontend — git видит чистое переименование, старый адрес 404.
  **Найдено и исправлено:** Claude сам создавал копию в новом разделе — бот
  теперь принимает это как перенос (удаляет старый файл).
- `/delete` без подтверждения — ничего не меняется (HEAD тот же, Claude не
  вызывался); с подтверждением — удалено, страница 404.
- `/undo` отменил удаление (страница снова 200); после ручного коммита `stan`
  — отказ: «последний коммит не от бота».

## Отступления от ТЗ и решения

- **kb-web** — свой модуль на stdlib вместо Caddy/`python -m http.server`
  (обоснование в этапе 2).
- `vue` добавлен прямой зависимостью `knowledge-base`: иначе VitePress пытается
  создать симлинк в `node_modules`, а они в контейнере только для чтения.
- Учебник и `index.md` раздела: в проверке frontmatter у `index.md` обязательны
  только `title` и `description` (у статей — все семь полей).
- **sudo на jade — sudo-rs:** не знает `requiretty` (убрал из sudoers).
- При «Сделай из этого статью» в чате нужна непустая сессия, иначе бот
  попросит тему.
- Перенос учебника целиком (папки) не поддержан — только отдельных статей.
- Бот шлёт «kb-bot запущен» (без звука) при каждом старте службы.

- **Ошибка, пропущенная ночью:** любое сообщение свободным текстом (и `/delete`)

  Поле `args` в `extra` логгера зарезервировано, а CLI ночью шёл без
  логирования и этого не воспроизводил. Исправлено. CLI теперь логирует так же,
  как служба (в stderr), добавлены тест с включённым логированием и проверка
  всех полей `extra` на зарезервированные имена.

- **Удаление разделов и учебников целиком:** «удали раздел Frontend»,
  `/delete учебник по Rust`. В подтверждении указано, сколько статей
